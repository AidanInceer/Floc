CI

Three workflows in .github/workflows/. Nothing here deploys — CI proves the code compiles, passes and keeps its schema honest. Shipping is a separate, manual act.

The jobs, briefly

  • verify — lint, typecheck, test, build, then the fitness functions (layering, dead code, tokens, contrast, bundle budget). Filtered to ...[base], so a docs-only change costs seconds.
  • changes — asks git whether apps/mobile/, packages/ or the lockfile moved, and gates the two mobile jobs on the answer.
  • mobile — Metro bundles both platforms. The phone app has no build script, so this is its build.
  • mobile-android — real native compile on JDK 17. Advisory: continue-on-error sits on the steps so the check run stays green.
  • migrations — re-runs db:generate; a dirty tree means a schema change shipped without a migration. Touches no database.
  • wireframes — plain HTML must stay self-contained.
  • Security — gitleaks over full history plus pnpm audit; also weekly on a cron, so an old secret still surfaces.
  • Sync develop — on every push to main, merges it back into develop so the next PR has no phantom conflicts.

Rules of thumb

  • A new push to the same branch cancels the previous run (concurrency), except the develop sync.
  • Permissions are contents: read everywhere but the sync, which needs write.
  • Node 22, pnpm, --frozen-lockfile, in every job.
