Architecture

The active app is floc/apps/web: Next.js App Router, Drizzle over Turso (libSQL), Better Auth, Stripe. Everything else in the repo is plumbing, docs, or superseded prior art.

Native iOS and Android apps are planned alongside it, sharing logic but not screens — see Web, iOS and Android.

Layers

  • @floc/core holds the domain rules and the closed sets they branch on. It is pure — no I/O, no DB, no next/* — and imports nothing from apps/web, so the phone apps can run the same rules (#286). db/schema.ts imports its vocabulary and re-exports it.
  • What stays in lib/ is what only a browser or Next can run: env, theme, tabs, map, auth-client.
  • server/ owns all SQL and all soft-delete filtering. One file per concept; a name needing an "and" is two files.
  • components/ take data, never fetch it.
  • Nothing in app/ imports @/db. pnpm deps:check enforces this.
  • server/freshness.ts is the only importer of next/cache. Everything else maps a fact to the pages it stales by calling refresh.
  • floc/apps/prototype is dead prior art. Don't extend it.

Request flow

Server Components by default; mutations are Server Actions in each route folder's actions.ts, never inline "use server" closures. No client-side fetch to our own API. app/api/* holds exactly two things — the Better Auth catch-all, and the Stripe checkout/portal/webhook handlers. Both need a real HTTP endpoint; nothing else does.

    participant Action as Server Action (actions.ts)

    Browser->>RSC: navigate to /trip/:id/:tab
    RSC->>Access: requireTripAccess(tripId, session)
    Access->>DB: membership check
    Access-->>RSC: trip context, or 404-equivalent
    RSC->>Gate: canUseFeature (Pro surfaces only)
    RSC->>Domain: read
    Domain->>DB: query (deletedAt IS NULL)
    Domain-->>RSC: view data
    RSC-->>Browser: rendered HTML

    Browser->>Action: form submit
    Action->>Access: requireTripAccess / assertAdmin
    Action->>Gate: assertFeature (writes behind Pro)
    Action->>DB: write (transaction where multi-row)
    Action-->>Browser: refresh + re-render

requireTripAccess is the only door into a trip. A non-member gets the same response as a trip that doesn't exist — enumeration-proof by construction, never a hand-rolled membership if.

The gate runs on writes and refreshes, never on reads. Lapsed Pro content stays readable forever; only the action stops.

Admin powers are exactly four — invite, kick, promote, delete/archive — each gated by assertAdmin. Everything else, leaving included, is any member.

Auth

Better Auth owns sessions. lib/auth-client.ts is the browser handle, server/auth.ts the server one. No custom session table, no hand-rolled JWT. It is a library, not a service — users live in our own Turso database and nothing is sent to better-auth.com.

Data model shape

Full detail in the ERD; the schema of record is db/schema.ts. Shape only:

erDiagram
    TRIP ||--o{ TRIP_MEMBER : has
    TRIP ||--o{ DAY : "day-first itinerary"
    DAY ||--o{ DAY_EVENT : has
    TRIP ||--o{ EXPENSE : has
    EXPENSE ||--o{ EXPENSE_SPLIT : "snapshots, never recalculated"
    TRIP ||--o{ NOTE : "polymorphic (scope + scope_id)"
    TRIP ||--o{ DOCUMENT : has
    TRIP_MEMBER ||--o{ AVAILABILITY : submits
    TRIP ||--o{ VOTE : has
    USER ||--o{ SUBSCRIPTION : holds

Rules the schema enforces, not just the diagram:

  • No stop table. A stop is derived by grouping consecutive day rows sharing an overnight_place_id. Storage is day-first.
  • No lifecycle state. Trip state derives from the data present — no enum, flag, column or tab gate. The last persisted lifecycle bits (the sticky tab-unlock flags) went with ticket 126.
  • Money is integer minor units, only ever through @floc/core/money. expense_split rows are write-once snapshots, so a member leaving cannot corrupt history.
  • Soft-delete everywhere — every read and write filters deletedAt IS NULL, with three documented exceptions.
  • Last-write-wins. No version column; last_modified_at is debug-only.
  • A trip may have no dates. start_date/end_date are nullable; undated is never an error.
  • No timezones. Dates are YYYY-MM-DD; event times are local to the itinerary, never stored with an offset.
  • Discussion is one polymorphic note table (scope + scope_id), not a comment table per feature.
  • Pro is one subscription row. A source column records stripe or comp; the gate never reads it. See Pro tier.

Deployment

  • Railway, via railway.json: run the migration, then start floc-web. Push to main deploys. Env vars live in the Railway Variables tab, never in the repo.
  • Uploaded documents sit on a mounted Railway volume, not in the database.
  • Data store: Turso (libSQL), reached only through db/index.ts.
  • Degrade without credentials, never crash. No Nominatim → free-text place names. No Resend key → email logged to console. No Google client → the button isn't drawn. No MapTiler key → plain OpenStreetMap tiles.
  • Light and dark are one token set switched by data-theme on <html>. No server state, no theme column.
  • Out of scope for v1, so deliberately absent: settlement and payment rails, POI and review data, flight booking, i18n, analytics, push notifications. Stripe is here for subscriptions only — it never touches the group ledger.
