Architecture

One web app, one phone app, one database. The web app (floc/apps/web) is the only part with credentials. The phone app (floc/apps/mobile) reads and writes through it. Detail per surface: Web, iOS and Android.

A new procedure needs a line in scripts/parity/parity.json. CI fails without it.

Rules of access
  • requireTripAccess is the only door into a trip. A non-member gets the same answer as a trip that does not exist.
  • The Pro gate runs on writes, never reads. Lapsed Pro content stays readable.
  • Exactly three admin powers — remove a member, promote, delete or archive. Each checks assertAdmin.

  • Money is integers in minor units. Only @floc/core/money does maths on it.
  • expense_split rows are written once. A member who leaves cannot change history.
  • FX is for display only. No balance comes from it. A cross-currency settlement stores its own rate.
  • fx_rate is a cache. It has no owner and no foreign keys. If Frankfurter is down, the newest cached day is shown with its date.
  • No payments between members. Settlements record money moved outside the app.

Files
  • Bytes sit on a Railway volume (FLOC_FILES_DIR). Rows sit in document.
  • Web reads bytes through trip/[id]/files/[docId]/raw, behind the session.
  • The phone lists, uploads and removes. It cannot open a file yet.

Rules the schema holds:

  • No stop table. A stop is consecutive days with the same overnight_place_id.
  • No lifecycle flags. Trip state comes from the data.
  • Soft-delete everywhere. Every read and write filters deleted_at IS NULL.
  • Last write wins. No version column.
  • Dates may be empty. start_date and end_date are nullable.
  • No timezones. Dates are YYYY-MM-DD. Times are local to the trip.
  • One note table for all discussion.
