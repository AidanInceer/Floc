Web, iOS and Android

Three surfaces, one repo. The web app runs on Railway. iOS and Android are one Expo app for the App Store and Google Play. Same behaviour everywhere. Native UI on each. Decision record: #237.

Shape

Logic is shared. Screens are not. The phone talks to the web app over tRPC.

Data

  • One database, server side. The phone never holds Turso credentials.
  • The phone reads and writes only through tRPC. tRPC calls the same server/ modules as the web, so access checks and soft-delete run once for both.
  • Drizzle row types stay in the web app. The phone reads the router's output types — a smaller shape.
  • depcruise blocks db/ imports outside apps/web.

Why tRPC, not REST

Behaviour must not drift. With tRPC, a changed server signature fails the phone typecheck. With REST it fails later, on a phone. A separate API app was refused: a second deploy for no gain.

Parity

Every procedure has a line in scripts/parity/parity.json: does the phone have it, and if not, why. CI fails on a missing line. pnpm parity checks locally.

Delivery

ChangeGoes byTime
WebRailway, on push to mainMinutes
Phone, JavaScript onlyEAS UpdateMinutes, no review
Phone, nativeEAS Build + store reviewDays

Native means: a package with native code added or upgraded; a permission, entitlement or bundle id changed; icon, splash or app name changed; Expo SDK bumped. An update may never change what the app is for. Full rule: floc/apps/mobile/SHIPPING.md. Store checklist: floc/apps/mobile/STORE.md.

  • The web version is in floc/apps/web/package.json. The phone keeps its own, bumped per store submission.
  • Mobile deps come from npx expo install, never pnpm add.
  • CI bundles both platforms and compiles Android (advisory). Store builds are never in CI. See CI.

Offline

Not built. The query cache can be saved to disk later (#226), so offline reads are a switch, not a rewrite. Offline writes are not promised: last write wins, so a late replay would overwrite someone (#169).

Phone gaps

Each is a decision, tracked in parity.json.

  • Open a file. The phone lists, uploads, moves and removes files. Bytes come from a cookie-only route, and there is no PDF viewer yet.
  • The /signup page. Sign-up, reset and new password work on the phone. Only the web page and its ?via= tracking stay web.
  • Work offline. See above.
